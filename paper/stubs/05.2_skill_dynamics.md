# §5.2 — Skill-bank dynamics during co-evolution

> **Reviewer ask** (NeurIPS 2026 R1): "we never see how the bank actually
> evolves — quote promotion / rejection / deprecation rates, mutation
> mix, and a long-tail retrieval distribution."

This section consumes the four reviewer-instrumentation streams emitted
by :mod:`trainer.coevolution._run_loggers`:

| stream | path | drives |
| ------ | ---- | ------ |
| lifecycle transitions | `lifecycle_log/transitions.jsonl` | promotion / deprecation curves, lifetime distribution |
| harness rejections | `harness_log/rejections.jsonl` | failure-mode pie chart |
| validate-invocation diagnostics | `harness_log/validate.jsonl` | retrieval long tail, mutation→repair table |
| crafter / promotion audit | `audit.jsonl` | mutation-operation pie |

## 5.2.1 Promotion / rejection / deprecation curves

Source: `lifecycle_log/transitions.jsonl`.
Generator: `python -m scripts.skillbridge_analysis.plot_skill_dynamics --run-dir <run-dir>`.

Reports cumulative counts of skills entering each canonical status
(`DRAFT` → `PROVISIONAL` → `ACTIVE` → `DEPRECATED` → `RETIRED`) over
trainer steps.  The summary JSON (`skill_dynamics_summary.json`)
publishes:

```text
counts_by_to_status = {
    "DRAFT":       N_draft,
    "PROVISIONAL": N_provisional,
    "ACTIVE":      N_active,
    "DEPRECATED":  N_deprecated,
    "RETIRED":     N_retired,
}
```

Plot reference: ``skill_dynamics_curves.png`` (Figure 5 candidate).

**Numbers to drop in here:**
- promotion rate    `N_active / N_provisional`
- deprecation rate  `N_deprecated / N_active`
- retire rate       `N_retired / N_active`

## 5.2.2 Crafter mutation mix

Source: `audit.jsonl` events tagged `crafter_mutation` (the `_crafter_hook`
emits these under `kind="crafter_mutation"`).
Generator: same as §5.2.1; pie chart `crafter_mutation_pie.png`.

Top-10 mutation operations are reported in absolute counts and as a
percentage of total proposals; the residual "other" bucket is shown
explicitly.

## 5.2.3 Per-skill retrieval long tail

Source: `harness_log/validate.jsonl` (one row per `validate_invocation`
call; the `ok=true` subset gives us "actually used in production").
Generator: `python -m scripts.skillbridge_analysis.plot_skill_long_tail --run-dir <run-dir>`.

Outputs `skill_long_tail.png` (linear + log-log axes) and a JSON
summary that gives:

* `n_unique_skills` — number of distinct skill_ids actually fired
* `n_total_retrievals` — total successful invocations
* `top_50` — `[(skill_id, count), …]`

The Pareto-style head/tail ratio (top-10 / total) is the headline
number.

## 5.2.4 Skill lifetime distribution

Source: same lifecycle log; right-censored at run end.
Generator: `python -m scripts.skillbridge_analysis.plot_skill_lifetime --run-dir <run-dir>`.

Plot: stacked histogram of lifetimes (died vs alive at run-end).  We
report the percentiles `{p10, p25, p50, p75, p90, p99}` so the median
matches the expectation that ACTIVE skills live ≫ rejected DRAFTs.

## 5.2.5 Harness failure-mode breakdown

Source: `harness_log/rejections.jsonl`.
Generator: `python -m scripts.skillbridge_analysis.plot_failure_modes --run-dir <run-dir>`.

The 8 canonical eligibility veto codes are charted as a pie:

```
status_not_runnable | shadow_disallowed | domain_mismatch | task_mismatch
skill_type_mismatch | no_adapter        | adapter_raised  | adapter_cannot_handle
```

Plus a second pie over the four `validate_invocation` failure axes
(`binding | precondition | evidence | adapter`).
