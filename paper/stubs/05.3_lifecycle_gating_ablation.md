# §5.3 — Lifecycle-gating and intention-trigger ablations

> **Reviewer ask** (NeurIPS 2026 R2): "you motivate the gated-promotion
> pipeline but never run the obvious ablation — what happens with the
> gate stripped out, and what happens if we always re-pick an
> intention?"

This section runs four ablations whose CLI flags now exist on
`scripts/run_coevolution.py`:

| ablation                          | flag                                                | baseline value |
| --------------------------------- | --------------------------------------------------- | -------------- |
| §5.3.1  no harness                | `--harness-mode off` / `plain-text-skills`          | `full`         |
| §5.3.2  no crafter                | `--no-crafter`                                      | crafter on     |
| §5.3.3  permissive promotion      | `--promotion-bypass-mode permissive`                | `gated`        |
| §5.3.4  intention trigger         | `--intention-trigger {sharp-shift, every-step, disabled}` | `every-step`   |
| §5.3.5  bank-size cap             | `--actor-bank-cap-K K`                              | `0` (uncapped) |

Each ablation is a separate co-evolution run starting from the same
SFT-warmed init.  Held-out performance is measured by the unified
cross-domain eval driver (`scripts/run_skillbridge_eval.sh`) and
aggregated by `scripts.skillbridge_eval.eval_aggregator` into a single
table with one row per ablation × domain.

## Reading order

1. **Headline table** — primary metric per domain × ablation.
2. **Skill-dynamics deltas** — for each ablation, re-run the §5.2
   plotting scripts on the ablation run-dir and report the delta in
   `{n_active, n_deprecated, retrieval long-tail head share}`.
3. **Failure-mode shifts** — for §5.3.1 (harness off) compare
   `harness_log/rejections.jsonl` veto-code shares against the full
   baseline.

## Significance testing

Each cell in the headline table is annotated with a paired-bootstrap
p-value computed by `scripts.skillbridge_analysis.compute_significance`
(5 000 resamples, paired by task id).  We follow the convention
``** p < 0.01``, ``* p < 0.05``.
