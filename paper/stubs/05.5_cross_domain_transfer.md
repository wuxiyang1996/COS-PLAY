# §5.5 — Cross-domain transfer matrix

> **Reviewer ask** (NeurIPS 2026 R3): "the system claims domain
> transfer; the only direct evidence I see is one Crafter snapshot
> evaluated on Crafter again."

We turn the per-phase snapshots produced by
`scripts/run_phase1_curriculum.sh` into a cross-domain transfer matrix:
each phase snapshot
``<run-dir>/phase_snapshots/phase_<k>_<game>/`` is independently
hot-swapped into the eval vLLM endpoint and run through every other
held-out domain.

Driver: `scripts.skillbridge_eval.run_transfer_matrix`.

```
python -m scripts.skillbridge_eval.run_transfer_matrix \
    --run-dir runs/skillbridge_v12 \
    --domains visual_reasoning video gymv \
    --vllm-base-url http://localhost:8000/v1 \
    --output runs/skillbridge_v12/eval/transfer_matrix.json
```

The matrix output is a 2-d JSON keyed by `(snapshot, domain)`, with
each cell holding the primary metric (success_rate_macro for
BrowserGym/OSWorld; accuracy_micro for visual_reasoning/video;
mean_reward_macro for gymv).  The training-domain cell is masked by
default (use `--include-self` to disable).

## Few-shot scaling sweep

Driver: `scripts.skillbridge_eval.run_few_shot_sweep`.  For each
target domain we sweep `k ∈ {0, 1, 4, 16, 64}` warm-up episodes and
report the post-warm-up primary metric.  This directly addresses the
reviewer's "is this just data efficiency?" concern.

## Headline plot

A single line plot per target domain with two series:

* x-axis: training-phase snapshot index (1..6).
* y-axis: primary metric on the target domain.
* curves: SkillBridge full vs. ``--harness-mode plain-text-skills``
  (the most informative ablation for transfer claims, since plain-text
  skills strip the binding contract).
